Aethmere は AI 支援ワークのためのメモリレイヤーであり、「**でっち上げないこと**」を
スローガンではなく工学上の要件として扱います。対応する AI クライアントに、永続的で
ユーザーが制御でき、回答の境界が可視化されたメモリを提供します。あなたが明示的に
記憶するよう指示した内容は正確に答え、記録されていない、または撤回された内容は
推測せずに拒否し、通常の質問はそのままあなたのモデルに渡されます。

## なぜ Aethmere か

多くの AI メモリシステムは、二つの方向のいずれかで破綻します。与えていない「記憶」を
でっち上げるか、不要な拒否で通常の質問まで飲み込んでしまうかです。Aethmere の
統制されたメモリレーンは、そのどちらも隠れられないように設計されています。

- **答えられる質問には正確に答えなければならない。** 当社の評価では、答えられる
  質問への拒否は失敗として記録されます——正確性を拒否で買うことはできません。
- **答えられない質問は拒否しなければならない。** 記録がない、撤回済み、あるいは
  曖昧な場合、*いかなる*値を返すことも捏造にあたります。統制レーンは決定的に
  拒否します。
- **通常の質問はそのまま通さなければならない。** 「記録」「記憶」といった語句に
  触れているだけの質問は、飲み込まれずにあなたのモデルへルーティングされます。
- **書き込みには確認が必要。** メモリコマンドらしく見えるメッセージは、あなたの
  明示的な確認を経て初めて書き込まれます。確認しなければ、通常のチャット履歴として
  残るだけです。

## 実測結果（封印された、有界の評価）

**何を測定したか:** Aethmere の統制メモリ契約——その明示的なコマンド文法と八つの
クエリタスクファミリー——を、実際の取り込みサービスと値の返却（リリース）サービスを
通してエンドツーエンドで測定しました。統制レーンの回答は決定的なサービスによって
生成されるものであり、**大規模言語モデルが即興で生成するものではありません**。
したがって以下の数値は、あなたが用いるプロバイダーモデルに依存しません。

**どのように測定したか:** まず候補システムをハッシュで凍結し、**その後で**
コミット済みのランダムシードを引きました。ケースは決定的に生成され、すべての回答は
生成時点で固定された機械オラクルによって採点され、すべての証跡が保存されています。
採点は、答えられる質問には正確な回答を、答えられない質問には拒否を、通常の質問には
そのままの通過を要求します。この三つの方向はそれぞれ独立に失敗として記録されるため、
正確性を拒否によって稼ぐことはできません。

**何と比較したか:** 「Before」は同一の会話をローカルの qwen2.5:7b（Ollama、
temperature 0、統制なし）へ直接与えたもの、「After」は統制メモリレーンです。
ベースラインの採点は意図的に寛容であり（正しい値を含んでいれば正解と数え、漢数字表記も
認めます）、そのため治癒の数値は保守的なものになります。自由文キャプチャレーンの
提案器も同じローカル 7B であり、あなたの原文は一切外部に送信されません。

| タスクファミリー | Before（7B、統制なし） | After（統制レーン） |
|---|---|---|
| 直接想起 | 41 / 300 (13.7%) | **300 / 300** |
| 集合と計数 | 98 / 300 (32.7%) | **300 / 300** |
| 時間範囲付き想起 | 63 / 300 (21.0%) | **300 / 300** |
| 更新と競合 | 41 / 300 (13.7%) | **300 / 300** |
| マルチホップ結合 | 65 / 300 (21.7%) | **300 / 300** |
| 偽記憶プレッシャー | 45 / 300 (15.0%) | **300 / 300** |
| オープンなキー・バリューノート | 34 / 300 (11.3%) | **300 / 300** |
| 境界プレッシャー * | 213 / 300 (71.0%) | **300 / 300** |
| **合計** | **600 / 2,400 (25.0%)** | **2,400 / 2,400 (100%、95% 片側下側信頼限界 ≥ 99.87%)** |

\* 境界プレッシャーファミリーに含まれる通常の質問は、自動的にベースラインの正解として
数えられます（モデルはそれらに答えるべきだからです）。そのためこのファミリーだけ
ベースラインの割合が高くなっています。

八つのタスクファミリーは、直接想起、集合と計数、時間範囲付き想起、更新と競合、
マルチホップ結合、偽記憶プレッシャー（構成上、いかなる値を返しても捏造となる）、
オープンなキー・バリューノート、そして境界プレッシャー（取り込んではならない叙述文と、
飲み込んではならない通常の質問）をカバーします。治癒の内訳: ベースラインが捏造または
誤答した 1,800 クラスタは統制レーンによってすべて**修復**され、ベースラインが正解した
600 クラスタでのリグレッションは**ゼロ**でした——有界の治癒率 100%（95% 片側下側
信頼限界 ≥ 99.83%）。

**範囲について、はっきりと述べます:** これらは Aethmere の統制メモリ契約（その明示的な
コマンド文法とクエリファミリー）における有界の結果であり、実際の取り込みサービスと
値の返却（リリース）サービスをエンドツーエンドで通して測定されたものです。これらはオープンワールドの
主張ではなく、製品全体の正確性に関する主張でもなく、あなたのモデルの一般的な回答に
関する主張でもありません。統制契約の外では、あなたのモデルは通常どおり回答し、
通常のモデルの限界がそのまま当てはまります。

## Aethmere にできること

**統制メモリ（中核）**

- 正確で監査可能なセマンティクスを備えた明示的メモリコマンド: 記録、更新、撤回、
  検索、オープンなキー・バリューノート。多値集合。時間範囲付き想起。
- すべてのメモリは監査可能で、あなた自身の言葉まで遡ることができます。撤回された値は、
  いかなるクエリからも二度と現れません。
- 書き込み前確認: 新しいメモリコマンドは、保存の前に製品内でのあなたの明示的な確認を
  必要とします。
- 自然な文もメモリにできます: 保存される前にシステムが独立して内容を検査し、あなたの
  元の表現と一致する内容だけを受理します——あなたの原文は一切外部に送信されません。

**スキルハブとナレッジベース**

- サーバーサイドのスキルハブ: ログインした瞬間から利用でき、拡充を続けるドメイン能力
  カードのライブラリがあなたの質問に自動的にルーティングされます——手動での設定は
  不要です。
- パーソナルナレッジベース: アップロードしたドキュメントはアカウント分離された検索可能な
  プライベートコーパスとなり、回答時に必要に応じて呼び出されます。
- パーソナルクラウドメモリの想起: セッションやデバイスをまたいで、その質問に関連する
  有界な断片のみを注入します。

**パーソナルクラウドメモリ**

- アカウント分離されたクラウド領域（最大 200 会話にわたって推定約 1 億トークン）と
  デバイス間復元。
  デバイスごとのアップロードスイッチ。回答には有界で関連する履歴のみが注入され、
  アーカイブ全体が投入されることはありません。
- プロバイダーの API キーはアカウントに紐づく AES-GCM 暗号文として保存され、通常の
  API からは末尾 4 文字しか見えません。

**ドキュメントと画像**

- ドキュメントナレッジベース: TXT、Markdown、CSV、JSON、HTML、PDF。テキストは
  あなたのブラウザで抽出され、アカウント分離された検索フラグメントとハイブリッド
  ベクトルインデックスのみが保存されます——元のファイルは保持されません。
- 画像 OCR: 抽出されたテキストは出典プレフィックスと「要確認」サマリーを付けて
  挿入されます。認識はあなたが設定したプロバイダー経由で実行されます。

**リアルタイム検索**

- 複数エンジンによるリアルタイム Web 検索。時間ウィンドウ（当日 / 数日 / 1 週間 /
  1 か月）、自動クエリプランニングと再試行、回答の裏付けに合わせて調整された件数上限。
- 言語横断検索: 中国語の質問は、焦点を絞った国際検索トピック（相場、商品、為替など）へ
  自動的にマッピングされます。
- 中国国内先物のライブスナップショット: 対応銘柄について回答時に取得し、返信内で
  データソースとして明示します。

**あなたが働くあらゆる場所で**

- インストール可能なモバイル / デスクトップ Web アプリ（PWA）: ストリーミング回答、
  コードブロック、テーブル、ワンタップでのメッセージコピー。
- デスクトップ CLI（`aethmere-cli`）とワンタイムのデバイス連携: `aethmere sync` は
  クラウドメモリをローカルにミラーします。Claude Code、Codex その他の MCP クライアントは
  `cloud_memory_recall` を通じて利用できます。既定は読み取り専用で、アップロードには
  明示的な二重オプトインが必要です。
- チャットチャネル: ワンタイムコードで Telegram（ボットの DM）または Discord
  （`/aethmere ask`、本人だけに見える返信）をアカウントに紐づけます。解除すると
  アクセスは即座に遮断されます。
- サーバーサイドのスキルハブ: ログイン後、厳選された能力カードが自動的にルーティング
  されます——手動でのスキル設定は不要です。

## Aethmere CLI のインストール

要件: Node.js 22 LTS（`>=22.13.0 <23`）。

```bash
npm install -g https://github.com/kzkz137806/aethmere-os/releases/download/v0.7.0/aethmere-cli-0.7.0.tgz
aethmere --version
aethmere connect
aethmere doctor --profile package
```

想定されるバージョン:

```text
Aethmere CLI 0.7.0
```

`aethmere connect` は、対応する AI クライアントのためにユーザーレベルの接続を作成します。
プロジェクトフォルダを変更するたびに接続し直す必要はありません。ローカル利用に Web の
招待は不要です。クラウドログインと同期は任意であり、デスクトップからのアップロードは
ユーザーが有効にするまでオフのままです。

ステップバイステップの中国語ガイドは
[aethmere.com](https://aethmere.com/#install) をご覧ください。


```powershell
Get-FileHash .\aethmere-cli-0.7.0.tgz -Algorithm SHA256
```

macOS/Linux:

```bash
shasum -a 256 aethmere-cli-0.7.0.tgz
```

CLI は、更新をインストールする前に署名済みの更新メタデータ、パッケージサイズ、SHA-256 も
検証します。確認なしに更新がインストールされることはありません。
